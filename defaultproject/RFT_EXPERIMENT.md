## 2. 왜 reader인가 — 운영점 `dig_order` 실측

**[확인됨]** `dig_order` = BM25 top-50 → RRF(UPR, ALR) → top-5 → SlotOrder(`edge_last`). n = 6,514.
전체 accuracy 0.3555가 `facts.json`의 값과 일치한다.

$$\text{acc} = P(m{>}0)\cdot P(e{=}1\mid m{>}0) + P(m{=}0)\cdot P(e{=}1\mid m{=}0)$$
$$= 0.6073 \times 0.5784 + 0.3927 \times 0.0109 = 0.3555$$

`m>0`에서 완벽하다고 가정하면 $0.6073 + 0.3927\times0.0109 = 0.6116$ → **+25.61pp**.
**도달 목표가 아니라 분해의 산술적 극한이다.**

## 3. 출력 계약 **[제안]**

```json
{"answer": "Cyndi Lauper", "source": 3}
```

v3의 JSON 계약 + `source`. `source`가 가리킬 대상이 있어야 하므로 **passage에 번호를 붙인다** — 즉 v3 대비 ① 번호 매김 ② 필드 추가 **두 가지가 동시에 바뀐다.** G1은 둘의 **합산 효과**를 재며, 둘을 분리하지 않는다.

`source=0`(근거 없음)이나 답변 보류는 **도입하지 않는다.** 출력 계약과 평가 규칙이 함께 바뀌는 별도 실험이다.

## 4. $m$ 과 $g_i$ — 정의와 한계

$$g_i = \mathbb{1}\big[\exists a \in A : \mathrm{norm}(a) \subseteq \mathrm{norm}(\text{title}_i + \text{text}_i)\big], \quad m=\sum_{i=1}^{5} g_i$$

**[확인됨]** $m$ 은 **모델에 실제로 전달된 5개**로 계산한다. 단위 검증 #4에서 $P(m{>}0)=0.6073$ 이 `facts.json`의 `dig_order` HasAnswer와 일치함을 확인했다.

**한계 — 단정하지 않는다**
- $g_i=1$ 이 의미적 근거를 뜻하지 않는다 (`1975` 같은 흔한 alias는 우연히 일치)
- $g_i=0$ 이 근거 없음을 뜻하지도 않는다 (alias 없이 답을 뒷받침할 수 있다)
- **[미확인]** 이 문자열 기준이 실제 근거 유무와 얼마나 어긋나는지는 재지 않았다

## 5. 보상

### 형식은 보상이 아니라 필터

$$\text{valid}(y)=\mathbb{1}[\text{JSON 파싱} \wedge \texttt{answer}\in\text{str} \wedge \texttt{source}\in\{1..5\}]$$

invalid 후보는 **보상을 계산하지 않고 제외**한다. 음수 보상을 주면 그룹 평균이 형식 오류 빈도에 휘둘린다. 형식 유효율은 별도 지표로 보고한다.

### 보상 함수 (valid 후보에 대해서만)

$$R(y) = e + \alpha\,e\,g_s - \beta\,(1-g_s), \qquad \alpha=0.3,\ \beta=0.5$$

| 결과 | $R$ |
|---|---|
| ① 맞힘 + source가 $g{=}1$ | **1.3** |
| ② 맞힘 + source가 $g{=}0$ | **0.5** |
| ③ 틀림 + source가 $g{=}1$ | **0.0** |
| ④ 틀림 + source가 $g{=}0$ | **−0.5** |

**필수 제약 ② > ③** — 우리 지표에서 ②는 정답, ③은 오답이다. 뒤집히면 자기 지표에 반하는 최적화가 된다. 이것이 $\beta<1$ 을 고정한다.
**지배성** — 정답의 보상 차(1.3, 1.0)가 source의 차(0.8, 0.5)보다 항상 크므로, 정답을 포기하고 source 점수를 사는 거래가 성립하지 않는다.

**주장하지 않는 것**
- $g_s=1$ 은 "문서를 활용했다"의 증거가 **아니다.** 고른 문서에 gold alias 문자열이 있다는 측정값이다
- 이 선호 순서가 전체 accuracy 향상을 **보장하지 않는다.** 필요조건이지 충분조건이 아니다
- **[미확인]** $\alpha,\beta$ 민감도는 재지 않았다

### $m=0$ 은 보상 0이 아니라 **학습 대상에서 제외**

데이터 필터로 처리한다(loss mask 아님 — 해당 질문의 어떤 토큰도 손실에 들어가지 않는다). $m=0$ 에서 맞힌 답은 문서를 읽어서 나온 것이 아니므로($P(e{=}1\mid m{=}0)=0.0109$) 보상하지 않는다.

**[제안] 이 선택의 위험**: "정답은 항상 프롬프트에 있다"는 사전을 강화해 $m=0$ 구간이 나빠질 수 있다. 그래서 **평가에서는 $m=0$ 을 유지**하고 중단 기준에 넣는다.

## 6. 알고리즘 — 보상 가중 RFT

$$\mathcal{V}_j = \{i : \text{valid}(y_j^{(i)})\},\quad
\mu_j,\sigma_j \text{ 는 } \mathcal{V}_j \text{ 에서만 계산}$$
$$\hat A_j^{(i)} = \frac{R(y_j^{(i)})-\mu_j}{\sigma_j+\epsilon}$$
$$\mathcal{T}_j = \{i \in \mathcal{V}_j : e^{(i)}=1 \wedge \hat A_j^{(i)}>0\}, \quad m_j>0$$
$$\mathcal{L} = \sum_j \sum_{i\in\mathcal{T}_j} w_j^{(i)}\,\ell(y_j^{(i)}),\qquad
w_j^{(i)} = \frac{\hat A_j^{(i)}}{\sum_{i'\in\mathcal{T}_j}\hat A_j^{(i')}}$$

**$e=1$ 조건이 필요한 이유**: $\hat A>0$ 만으로는 **평균보다 보상이 높은 오답**(③ 0.0 이 그룹 평균 −0.3보다 높은 경우)이 학습에 들어간다.

**[확인됨]** $\ell$ 은 **토큰 평균**이다. `transformers 4.52.4`의 `fixed_cross_entropy`는 `num_items_in_batch=None` 일 때 `reduction="mean"` 을 쓴다. 프롬프트는 `labels=-100`.

**$\sum_i w = 1$ 의 의미 제한**: 질문마다 **손실 항의 가중치 합**이 같다는 뜻일 뿐, 질문별 학습 영향이 같다는 뜻이 아니다. 기울기 크기는 모델이 얼마나 틀렸는지·토큰 수·분포에 따라 다르다.

**학습 타깃**: 파싱된 필드의 **정규 JSON**을 쓴다(원문 생성 그대로가 아님). 내용은 모델 자신의 것이되 닫는 중괄호 뒤의 군더더기는 버린다.

### GRPO는 조건부 — 기본값 아님

포화 시 **원인부터 진단**한다. GRPO가 자동 해결한다고 가정하지 않는다.

| 포화 원인 | 진단 | GRPO가 답인가 |
|---|---|---|
| 데이터 부족 | 유지 질문 수 | 아니다 |
| 후보 다양성 부족 | $\sigma_j{=}0$ 비율 | 아니다 ($T,G$ 문제) |
| 보상 신호 부족 | 적중률↑ accuracy 정체 | 아니다 (보상 재설계) |
| **음성 샘플 미사용** | $\mathcal{T}_j{=}\varnothing$ 인데 $\mathcal{V}_j$ 에 정보 있음 | **그렇다** |

## 7. 디코딩 — 용도별 분리

| 용도 | 설정 |
|---|---|
| 학습 후보 생성 | sampling, $G{=}8$, $T{=}0.9$ |
| G2 pass@8 | sampling 8개 채점 |
| G1 · C1 · RFT 단일 답변 | **greedy** (기존 하네스) |

- **greedy**는 매 스텝 최고확률 토큰을 고르는 결정적 디코딩이다. 정답을 보장하지 않는다. 기존 모든 표가 greedy라 **비교 가능성 때문에** 유지한다.
- **pass@8**은 gold를 써서 8개 중 하나라도 맞았는지 보는 진단이다. 단일 답변 정확도가 아니고 **학습 후 성능의 절대 상한도 아니다.**

## 8. 학습 데이터 **[확인됨 — 생성 완료]**

`bm25_train.jsonl`(10,000질문 × top-20) + `select_train.jsonl`의 $g$ 라벨 재사용. **NQ train split만** 사용(`DEV_GUARD`). dev 정답은 채점에만 쓴다.

세 분포를 평가 설정에 맞춘다 — 안 맞추면 구성 방식을 학습한다.

### 왜 쿼터 배정인가

질문마다 $M_{\text{target}}$ 에서 독립으로 뽑으면 **m=1이 56.1%로 쏠린다**(목표 30.4%). 정답 보유 passage가 하나뿐인 질문은 m=1밖에 못 하고, 더 할 수 있는 질문도 $M_{\text{target}}$ 이 m=1에 치우쳐 m=1을 고른다. **제약이 심한 질문부터 처리하며 남은 쿼터에 비례 배정**하면 전역 분포가 목표에 맞는다.

### 칸 분포 — 위치 지름길 방지

평가에서 `edge_last`는 RRF 1위를 **5칸**에 놓는다. 실측하니 $m{=}1$ 일 때 정답 passage가 5칸에 **51.3%**, 나머지 칸은 10~15%다. **늘 5칸에 두면 위치를 학습하고, 균등하게 두면 평가와 어긋난다.** 그래서 측정한 분포를 맞췄다.

| 칸 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 생성 | 0.592 | 0.426 | 0.390 | 0.498 | 0.729 |
| dev 실측 | 0.613 | 0.400 | 0.360 | 0.493 | 0.769 |

비복원 순차 추출이라 완전 일치는 안 된다. $m$ 별로는 $m{=}1$ 이 거의 정확(0.152/0.102/0.095/0.123/0.528 vs 0.154/0.097/0.108/0.127/0.513)하고 높은 $m$ 에서 몇 pp 어긋난다.

**[제안]** distractor는 BM25 상위의 정답 미보유 passage를 쓴다 — 랭커가 실제로 올릴 법한 것이지 꼬리에서 임의로 뽑은 것이 아니다.

## 10. 통제군과 비교

| | 설정 | 분리되는 것 |
|---|---|---|
| **G1** | base + source 형식, 학습 없음, greedy | 계약 변경 자체의 효과 |
| **G2** | base, sampling $G{=}8$ | 후보 다양성 |
| **C1** | gold SFT, 동일 질문·컨텍스트·형식 | 지도학습 대비 RFT의 추가분 |
| **RFT** | 1~3회전, greedy | |

- **주 비교: RFT vs G1** — 같은 형식이므로 학습 효과만 분리된다
- **부 비교: RFT vs `dig_order`(0.3555)** — 형식 효과가 섞인다. 기존 표와 잇기 위해 별도 보고
- 둘 다 `analyze_position.py`의 페어드 McNemar

**C1 타깃 기준 [제안]**: `answer`는 train gold alias 첫 번째, `source`는 $g_i{=}1$ 중 BM25 최상위.
**학습 예산을 맞추지 않는다** — RFT는 샘플링+3회전, C1은 1회 SFT다. "RFT > C1"이 알고리즘 우위인지 예산 차이인지 단정하지 않는다.

### HasAnswer 고정

**[확인됨]** `prompt_rag.py`의 `ctx_token_budget` 기본값 `None` → passage가 잘리지 않는다. 컨텍스트 131,072 토큰, 현재 프롬프트 ~1,121 토큰이라 source 지시문으로 잘림이 **구조적으로 불가능**하다.
**[미확인]** G1 전체 실행에서 HasAnswer가 0.6073에서 안 움직이는지 실측 확인한다.

## 11. 중단 기준

| 위험 | 계측 | 기준 |
|---|---|---|
| 영분산 | $\sigma_j{=}0$ 비율 | > 70% → $T,G$ 상향, 그래도면 중단 |
| 학습 후보 고갈 | $\mathcal{T}_j{=}\varnothing$ 비율 | 유지 질문 < 목표의 1/3 → 재설계 |
| 형식 퇴행 | G1 유효율·accuracy | 붕괴해도 **보고하고 진행** (사전 결정) |
| **$m{=}0$ 악화** | $m{=}0$ accuracy, 프롬프트 밖 비율 | 유의하게 나빠지면 $m{=}0$ 일부 재투입 |
| 보상 해킹 | 적중률↑ `m>0` accuracy 정체 | $\alpha$ 하향 후 재실행 |

**번호 매김 + `source` 필드 추가는 학습 없이는 정확도를 3.77pp(m>0) 깎는다.** 유의하다. 형식은 멀쩡하므로(99.89%) v4_cot 같은 붕괴는 아니고, 과제가 하나 늘어난 만큼의 비용이다.

**HasAnswer가 소수점 끝자리까지 동일하다** — §10의 코드 근거(`ctx_token_budget=None`)가 실측으로 확인됐다. 검색은 손대지 않았고 바뀐 것은 reader뿐이다.

**이 수치가 주 비교 기준이다.** RFT는 `dig_order` 0.3555가 아니라 **`rft_g1` 0.3316 / m>0 0.5407** 을 넘어야 학습 효과라고 말할 수 있다.

### source 적중률 0.5520 **[확인됨]**

$P(g_s{=}1 \mid m{>}0,\ \text{valid})$. 정답 보유 passage가 프롬프트에 있을 때, 모델이 지목한 문서가 실제로 gold alias를 품은 비율이 **55.2%** 다. 보상 $r_2 \cdot r_3$ 가 올리려는 양의 출발점이며, 학습 후 이 값이 오르는지가 보상이 작동했는지의 직접 증거다.

### 같은 기준에서 다시 본 상한

$$0.6073 \times 1 + 0.3927 \times 0.0082 = 0.6105$$

`rft_g1` 0.3316 기준 **+27.9pp**. 역시 도달 목표가 아니라 분해의 산술적 극한이다.

## 14. 보고 시 주의

reader를 학습시키면 `naive RAG 0.2451 → 0.3556` 의 성격이 바뀐다. 지금까지는 **"같은 생성기, 더 나은 검색"** 이었다. 이제 축이 둘이므로 표를 분리해야 한다.

- 검색 축: `RAG + JSON + K_POOL + ALR + SlotOrder` (생성기 고정)
- reader 축: `+ RFT` (검색 고정)

섞어서 하나의 숫자로 보고하면 기존 결과의 해석이 무너진다.
