## 1. 설계 요약

| | |
|---|---|
| **학습 대상** | 선택기만 (LoRA r=16, q/k/v/o, 3,407,872 / 1,239,222,272 = **0.275%**) |
| **고정** | 답변 생성기 (v3 reader, 어댑터 없음) |
| **출력** | `{"sources": [오름차순 정수]}`, 0~5개. 빈 목록도 정상 출력 |
| **입력** | dig_order의 top-5 — BM25 top-50 → **RRF**(UPR, ALR) → top-5 → `edge_last` |
| **보상** | $n>0$: $2TP/(n+k)$ · $n=0,k=0$: 1 · $n=0,k>0$: 0 · 형식오류: −1 |
| **답변 정오** | **보상에 없음.** 평가 지표로만 사용 |
| **알고리즘** | trl 1.14.1 `GRPOTrainer`, G=8, T=0.9, β(KL)=0.04, ε(clip)=0.2, lr=1e-5 |

**2단계 호출 [확인됨]**: 선택기 LoRA는 **꺼진 상태가 기본**이고 선택할 때만 `selector_active()` 안에서 켜진다. 답변 생성은 하네스가 `rag.model`에서 수행하므로 항상 꺼진 상태로 돈다. `verify_two_call.py` 8개 검사 전부 통과 — 어댑터 적재 전후 reader 출력이 바이트 단위로 동일(`['Kenny Loggins']`), 기본 가중치 불변, 예외 후 상태 복원.

**라벨 한계**: $g_i$ 는 정규화된 gold alias의 **부분문자열 일치**다. 의미적 근거를 검증하지 않는다.

## 3. 주 비교 B → C

```
답변 정확도   0.2698 → 0.3487   (+7.9pp)   z=17.11  p=1.2e-65
선택 F1       0.3898 → 0.6370   (+24.7pp)
정밀도        0.5421 → 0.6352
재현율        0.4560 → 0.7573
형식 유효율   0.9349 → 1.0000
```

**선택 품질과 답변 정확도가 함께 올랐다.** 셋 중 가장 해석하기 쉬운 경우이고, "선택만 올랐다"나 "답만 올랐다"가 아니므로 근거 선택 개선이 답변 개선으로 이어졌다고 말할 조건을 만족한다.

**[해석] 다만 이것만으로 "GRPO가 우월하다"고 말할 수 없다.** 같은 입력·라벨로 선택기를 **지도학습**한 비교군이 없다. B→C는 "선택기를 학습하면 좋아지는가"에 답하고, "GRPO가 다른 학습법보다 나은가"에는 답하지 않는다.

## 4. 결정적 한계 — C가 A에 진다

$$\texttt{msel\_c}\ 0.3487 \;<\; \texttt{msel\_a}\ 0.3552$$

**학습된 선택기가 5개를 그냥 다 넣는 것보다 못하다** (B→A z=17.98 가 B→C z=17.11 보다 크다). 차이는 −0.7pp로 작지만, 선택이라는 추가 단계를 거치고도 못 넘었다.

### 어디서 지는가 — $n>0$ 이다

| | n=0 (2,559) | n>0 (3,956) |
|---|---|---|
| `msel_a` | 0.0109 | **0.5779** |
| `msel_c` | 0.0113 | 0.5670 |

$n=0$ 에서는 둘이 같다(둘 다 문서를 준다). **$n>0$ 에서 1.1pp 진다.**

### 왜 — 재현율이 정밀도보다 중요하다 **[해석]**

| 설정 | 재현율 | 정밀도 | 답변 n>0 |
|---|---|---|---|
| `msel_oracle` | 1.000 | 1.000 | **0.6302** |
| `msel_a` | **1.000** | 0.527 | **0.5779** |
| `msel_c` | 0.757 | 0.635 | 0.5670 |
| `msel_e` | 0.356 | **0.769** | 0.5404 |

**재현율 순으로 정렬된다.** 정밀도가 가장 높은 `msel_e`(0.769)가 답변은 가장 나쁘고, 정밀도가 가장 낮은 `msel_a`(0.527)가 oracle 다음으로 좋다. 이 reader에게는 **정답 문서를 빠뜨리는 비용이 쓸모없는 문서를 넣는 비용보다 크다.**

Dice 보상은 정밀도와 재현율을 **대칭으로** 다룬다. 그 가중이 이 reader의 실제 손익과 맞지 않는다.

## 5. 기권이 무너졌다

| | n=0 기권률 |
|---|---|
| B (학습 전) | 0.2864 |
| **C (학습 후)** | **0.0039** |

보상은 $n=0$ 에서 기권에 1점을 주는데 정책은 **거의 기권하지 않게** 학습됐다. 학습 중 평균 보상 0.3512가 "항상 빈 목록" 상수 정책(0.3927)보다 낮았던 이유다.

**[해석] 그런데 답변 지표로는 손해가 아니다.** $n=0$ 에서 기권하면 0.0551, 문서를 주면 0.0113 — 기권이 5배 낫지만 둘 다 작고, $n=0$ 이 39.3%라 전체에 미치는 차이는 약 1.7pp다. 보상이 요구하는 행동과 답변 정확도가 요구하는 행동이 **이 구간에서 어긋난다.**

## 6. k 가 질문에 적응하지 않는다 **[확인됨]**

`msel_c` 의 선택 개수 분포 (greedy, dev 6,515):

| k | 0 | 1 | 2 | **3** | 4 | 5 |
|---|---|---|---|---|---|---|
| 문항 | 16 | 364 | 445 | **4,831** | 577 | 282 |
| 비율 | 0.2% | 5.6% | 6.8% | **74.1%** | 8.9% | 4.3% |

**74%에서 정확히 3개를 고른다.** 실제 $n$ 분포는 `{0: 39.3%, 1: 18.5%, 2: 14.0%, 3: 10.0%, 4: 7.9%, 5: 10.5%}` 로 $n=0$ 이 가장 흔한데, 정책은 거의 항상 3개다. 완전일치율이 0.1329 → 0.0639 로 **떨어진** 이유다.

학습 중(T=0.9 샘플링)에는 k=3이 41.8%였는데 평가(greedy)에서 74.1%로 더 좁아졌다.

### k별 답변 정확도

| k | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| `msel_c` | 0.062 | 0.275 | 0.330 | **0.343** | 0.430 | 0.422 |
| `msel_b` | 0.111 | 0.233 | 0.279 | 0.321 | 0.410 | 0.414 |

**[해석]** 두 설정 모두 k가 클수록 답변이 좋다. 다시 재현율 우위를 가리킨다. 다만 k가 큰 질문이 원래 쉬운 질문일 수 있어 **인과가 아니다.**

## 7. n별 선택·답변

| 설정 | n=1 (1,204) | n=2 (910) | n=3 (649) | n=4 (512) | n=5 (681) |
|---|---|---|---|---|---|
| `msel_a` F1 / acc | 0.333 / 0.311 | 0.571 / 0.537 | 0.750 / 0.689 | 0.889 / 0.771 | 1.000 / 0.852 |
| `msel_b` F1 / acc | 0.237 / 0.187 | 0.369 / 0.357 | 0.451 / 0.529 | 0.484 / 0.619 | 0.559 / 0.734 |
| **`msel_c`** F1 / acc | **0.430** / 0.299 | **0.648** / 0.529 | **0.755** / 0.675 | 0.771 / 0.764 | 0.775 / 0.841 |
| `msel_e` F1 / acc | 0.513 / 0.282 | 0.501 / 0.492 | 0.441 / 0.636 | 0.380 / 0.750 | 0.333 / 0.814 |
| `msel_oracle` F1 / acc | 1.000 / 0.452 | 1.000 / 0.565 | 1.000 / 0.712 | 1.000 / 0.768 | 1.000 / 0.852 |

**C는 n이 작을 때 A보다 F1이 높고(n=1 0.430 vs 0.333, n=2 0.648 vs 0.571) n이 클 때 낮다**(n=5 0.775 vs 1.000). 항상 3개를 고르니 당연한 결과다. 그런데 **답변 정확도는 전 구간에서 A보다 낮거나 같다** — 선택 F1이 좋아진 구간에서도 답변이 좋아지지 않았다.

## 8. 가설 판정

| | 답변 정확도 | vs A |
|---|---|---|
| 완벽한 선택 `msel_oracle` | **0.4041** | **+4.9pp** |
| 학습된 선택 `msel_c` | 0.3487 | **−0.7pp** |
| 현재 시스템 `msel_a` | 0.3552 | — |

**가설은 살아 있다** — 선택을 완벽히 하면 현재 시스템을 4.9pp 넘는다. $n>0$ 만 보면 0.6302 vs 0.5779 로 +5.2pp다.

**GRPO로 도달한 지점은 아직 "그냥 다 넣기"에 못 미친다.** 선택 F1은 0.3898 → 0.6370 으로 크게 올랐지만, 완벽(1.0)까지 아직 멀고 그 거리가 답변 정확도의 역전을 못 만들었다.

### 상수 정책 기준선 **[확인됨]** — 보상을 0 대비로 읽지 말 것

| 정책 | 보상 | 대응 |
|---|---|---|
| 항상 빈 목록 | **0.3927** = $P(n{=}0)$ | 조건 D |
| 항상 전부 | 0.3906 | 조건 A 입력 |
| 항상 [5] | 0.2735 | 조건 E |

| 완벽 선택 | 1.0000 | — |

**"항상 빈 목록" 0.3927은 성능이 아니라 $n=0$ 의 비율 그 자체다.** 질문을 읽지 않고 받는 공짜 점수다. 학습된 정책의 0.3512는 **그보다 낮다.**

그리고 **"근거가 있나 없나"만 완벽히 맞혀도 0.7833을 받는다** — "어느 문서인가"가 설명하는 몫은 **0.2167뿐**이다. 보상 상승을 근거 선택 품질 개선으로 바로 읽으면 안 된다.

## 10. 부수 발견 — few-shot 예시 순서가 정책을 붕괴시킨다

처음 예시를 `[선택 시연 → 기권 시연]` 순으로 넣었다. few-shot 모델은 **마지막 시연을 가장 강하게 모방**한다.

| 프롬프트 | n>0 빈선택 | 선택F1 | 답변 | 평균k |
|---|---|---|---|---|
| 기권 시연이 마지막 (`msel_b0`) | **0.7174** | 0.1348 | 0.1722 | 0.66 |
| 선택 시연이 마지막 (`msel_b`) | 0.2214 | 0.3898 | 0.2698 | 2.05 |

**정답 보유 문서가 있는 질문의 71.7%에서 빈 목록을 냈다.** GRPO 스모크에서 영분산이 **78.8%** 로 측정돼 학습 자체가 불가능한 상태였다. 순서를 뒤집자 영분산이 20%대로 내려왔다.

**[주의]** 같은 결함이 `selector_rft.py`(단일 선택, 미실행)에 남아 있다 — `SELECT_EXEMPLARS`가 선택 먼저, 기권 나중이다.

## 11. 한계

1. **학습 예산** — 1,500문항 1 epoch. 6,000문항은 측정 27초/스텝에서 11시간이라 줄였다. 더 돌리면 달라질 수 있다 **[미확인]**.
2. **GRPO 우위를 주장할 수 없다** — 같은 입력·라벨의 선택기 지도학습 비교군이 없다.
3. **C vs A는 알고리즘 효과만이 아니다** — 문서 수(5 → 평균 3)와 입력 구성이 함께 바뀐다.
4. **문자열 라벨** — $g_i$ 는 부분문자열 일치다. `1975` 같은 흔한 alias는 우연히 맞고, alias 없이 답을 뒷받침하는 문서는 0이 된다. 선택 F1 상승이 의미적 근거 선택 개선이라고 단정할 수 없다 **[미확인 — 괴리 크기 미측정]**.
5. **중복 문서** — Dice 보상은 같은 사실을 담은 문서 2개를 **둘 다** 골라야 만점을 준다. 최소 충분 근거를 찾는 보상이 아니다.
6. **train/eval 입력 차이** — train pool 깊이 20, dev 50. 같은 파이프라인이지만 passage 품질이 같지 않다. n 분포는 train `{0:42.0%, 1:20.1%, 2:14.7%, 3:9.2%, 4:6.6%, 5:7.4%}` vs dev `{39.3, 18.5, 14.0, 10.0, 7.9, 10.5}`.
7. **선택된 문서를 reader가 실제로 활용했는지는 확인하지 않았다.** 답변 정확도는 활용의 증거가 아니다.
8. **영분산 43.1%** — 그룹의 43%가 학습에 기여하지 못했다.
