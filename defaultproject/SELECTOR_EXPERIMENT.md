# Selector GRPO — 근거 선택을 직접 학습하는 실험

> 기존 reader RFT(`RFT_EXPERIMENT.md`)와 **별개 실험**이다. 산출물 이름은 `sel_*`,
> 출력 경로는 `output/selector/`. 기존 `rft_*` 결과·체크포인트는 건드리지 않는다.
>
> **[확인됨]** 측정했거나 코드를 읽은 것 · **[제안]** 설계 결정 · **[미확인]** 실행해야 아는 것

---

## 1. 목표와 가설

**직접 학습하는 것**: 질문에 답할 근거가 있는 passage를 고르거나, 적절한 근거가 없으면 고르지 않는 능력.

**가설**: 근거 선택이 좋아지면 **답변 생성 모델을 추가 학습하지 않아도** 최종 정확도가 개선될 수 있다.

답변 정확도는 **평가 지표로만** 쓰고 보상에 넣지 않는다. 그래야 "선택은 좋아졌는데 답은 안 좋아졌다"가 검출된다.

---

## 2. 확인한 사실

### 융합 방식은 RRF다 **[확인됨]**

`improved_rag.py:211 _rrf` — $\sum_r 1/(k + \mathrm{rank}_r)$, `rrf_k = 60`.
**Reciprocal Rank Fusion**이며 "RRT"가 아니다. 용어만 바로잡았고 알고리즘은 건드리지 않았다.

### 환경 **[확인됨]**

- `trl 1.14.1` 설치 가능 → `GRPOTrainer` 사용. **직접 구현하지 않는다**
- `cse402` 도커 이미지, Git Bash에서 `MSYS_NO_PATHCONV=1`, RTX 5080 16GB
- `peft 0.21.1`

### 입력 top-5는 그대로 둔다 **[확인됨]**

`SelectedPassageRAG`는 `ImprovedRAG.search()`를 그대로 호출해 dig_order의 top-5(RRF 융합 + `edge_last`)를 받고, **그다음에만** 개입한다. 검색·UPR·ALR·융합·순서 로직을 수정하지 않았고 oracle 문서를 끼워 넣지도 않는다.

---

## 3. 보상이 측정하는 것 — 상수 정책 기준선 **[확인됨]**

`python selector_baselines.py`, dev 6,514문항, dig_order top-5 `edge_last` 순서.
n>0 3,956 (60.7%) · n=0 2,558 (39.3%)

| 정책 | 보상률 | n>0에서 | n=0에서 |
|---|---|---|---|
| 항상 기권 | 0.3927 | 0.0000 | 1.0000 |
| slot 1 고정 | 0.3726 | 0.6135 | 0.0000 |
| slot 2 고정 | 0.2429 | 0.3999 | 0.0000 |
| slot 3 고정 | 0.2185 | 0.3597 | 0.0000 |
| slot 4 고정 | 0.2994 | 0.4929 | 0.0000 |
| **slot 5 고정** | **0.4670** | 0.7690 | 0.0000 |
| **n>0 판정만 완벽 + slot 5** | **0.8597** | 0.7690 | 1.0000 |
| 완벽 선택 | 1.0000 | 1.0000 | 1.0000 |

### 이 표가 말하는 것

**"근거가 있나 없나"만 완벽히 맞히고 어느 passage인지는 전혀 안 읽어도 0.8597을 받는다.** "어느 passage인가"가 설명하는 몫은 **0.1403뿐**이다.

그런데 기권 판정은 **최종 정답률과 가장 무관한 성분**이다 — n=0 질문에서 기권하면 reader는 passage를 못 받고, 그 구간 정확도는 dig_order에서 이미 0.0109다.

**따라서 보상 상승 ≠ 근거 선택 개선이다.** 결과는 항상 0.4670(최고 상수)과 **0.8597(기권 판정만 완벽)** 두 선과 함께 읽어야 한다. 학습 후 0.82가 나오면 쉬운 절반도 못 배운 것이다.

이것이 n>0 적중률 / n>0 기권률 / n=0 기권률 / n=0 오선택률을 **분리 보고**해야 하는 이유다.

## 4. 출력 계약과 보상 **[제안]**

```json
{"source": k}      k = 0..5
```

`k=0`은 "근거로 쓸 passage 없음"이라는 **정상 행동**이지 형식 오류가 아니다.

| 조건 | 선택 | 보상 |
|---|---|---|
| n > 0 | 정답 근거 passage 중 하나 | **Good = 1** |
| n > 0 | 다른 passage 또는 `source=0` | **Bad = 0** |
| n = 0 | `source=0` | **Good = 1** |
| n = 0 | passage 1~5 | **Bad = 0** |
| — | 파싱 실패·범위 밖 | **−1**, 유효율 별도 기록 |

최종 답변의 정오는 보상에 **들어가지 않는다**. 단위 검증에서 `reward()`의 인자에 정답이 없음을 기계적으로 확인했다.

### n = 0도 학습한다

"근거 없음" 선택이 학습 대상이므로 제외하지 않는다. (reader RFT 실험에서 m=0을 뺐던 것과 반대 선택이며, 거기서 플래그했던 "정답은 항상 있다는 사전 강화" 위험을 정면으로 다룬다.)

## 5. 라벨의 한계 **[확인됨 — 단정하지 않음]**

$g_i$ 는 **정규화된 gold alias가 passage 텍스트에 부분문자열로 있는가**다. `utils/metrics.py`의 `normalize_answer` 기준(소문자·구두점 제거·관사 제거·공백 정규화).

- $g_i=1$ 이 의미적 근거를 뜻하지 **않는다** (`1975` 같은 흔한 alias는 우연히 일치)
- $g_i=0$ 이 근거 없음을 뜻하지도 **않는다**
- **[미확인]** 이 괴리의 크기는 재지 않았다

**이 때문에 선택률이 올라도 정답률이 안 오를 수 있다.** 그 경우를 "근거 선택 개선의 효과"라고 쓰지 않는다.

gold·라벨·$n(q,D)$ 는 보상과 평가에만 쓰고 **모델 입력에 넣지 않는다.** train 정답은 학습 보상에, dev 정답은 출력 이후 채점에만 쓴다.

## 6. Selector와 Reader 분리 **[제안 — 검증 코드 작성됨]**

| | |
|---|---|
| **Selector** | 질문 + top-5 → `{"source": k}`. **GRPO로 학습** |
| **Reader** | 선택된 passage 하나(또는 없음) → 답변. **가중치 고정, 어댑터 미적용** |

Reader는 기존 v3 reader 그대로다. Selector 어댑터는 **base 모델의 별도 복사본**에 올린다 — 같은 모델에서 어댑터를 켜고 끄는 방식은 context manager 하나를 놓치면 학습된 가중치로 답변하게 되고, 그게 바로 이 실험이 아니라고 주장하는 것이다.

`check_reader_isolation.py` 가 두 가지를 본다:
1. reader 모듈 트리에 PEFT 레이어가 없는가
2. **같은 프로세스에서 어댑터를 적재한 전후로 reader 생성 결과가 바이트 단위로 같은가**

`source=0` 이면 **원래 top-5로 되돌아가지 않고 passage를 제공하지 않는다.** 이 규칙은 B와 C에 동일하게 적용된다. 형식 오류도 기권으로 폴백하되 유효율에 기록된다.

## 7. GRPO **[제안]**

`trl 1.14.1`의 `GRPOTrainer`. 직접 구현하지 않는 이유는, 틀리기 쉽고 틀려도 눈에 안 띄는 부분들을 이미 처리하기 때문이다 — old 로그확률 고정, 동일 토큰·동일 prefix 비교, temperature 일관 처리, 보상·reference에 gradient 없음, 생성 토큰에만 손실 적용.

우리가 소유하는 것은 **보상 함수**뿐이다.

| 설정 | 값 |
|---|---|
| G (num_generations) | 8 |
| T | 0.9 |
| β (KL 계수) | 0.04 |
| ε (clip) | 0.2 |
| LoRA | r=16, q/k/v/o |

좋은 후보만 남겨 SFT하던 필터는 **제거**했다. 양·음 어드밴티지를 모두 쓴다.
영분산 그룹 비율·형식 오류율·실제 학습에 쓰인 그룹 수를 `grpo_stats.json` 에 기록한다.

**[미확인]** 이진 보상(1/0/−1) + 6-way 행동이라 영분산 비율이 등급 보상 때(21%)보다 높을 수 있다. 스모크에서 재고 70% 넘으면 중단한다.

## 8. 비교 조건

| | 조건 | 비고 |
|---|---|---|
| **A** | top-5 전체 → 고정 reader | `dig_order` 와 동일. 이미 측정됨 **0.3555** |
| **B** | 학습 전 selector → 고정 reader | |
| **C** | GRPO 학습 후 selector → 고정 reader | |
| 진단 | **Oracle-1** — 완벽 선택(n>0이면 정답 보유 최상위 1개, n=0이면 기권) | gold 사용. 시스템 성능 아님 |
| 진단 | **Abstain-all** — 항상 passage 0개 | `source=0` 의 실제 비용 |

**주 비교는 C vs B.** selector 가중치만 다르고 입력·출력 형식, `source=0` 처리, reader 가중치, 디코딩이 전부 같다.
**C vs A는 문서 수(5→1)와 입력 구성 변화가 섞이므로 전부 강화학습 효과라고 설명하지 않는다.**

### Oracle-1 이 먼저인 이유 **[미확인 — 최우선 측정]**

passage 5개 → 1개는 큰 변화인데 **reader를 1개로 돌려본 적이 없다.** 위치 효과(1칸 0.3009 → 5칸 0.4663)도 전부 5칸 구조에서 잰 것이다.
**Oracle-1이 0.3555보다 낮으면 완벽한 selector로도 현재를 못 넘는다 — 학습 전에 가설이 죽는다.**

**n=0 비율을 맞추는 게 중요하다** — §3에서 보듯 보상의 86%가 기권 결정에 달려 있어서, train의 n=0 비율이 어긋나면 정책이 과하게 기권하거나 전혀 기권하지 않는다.

**알려진 차이 [확인됨]**: train 컨텍스트는 **BM25 top-20**에서 구성했다. train split에는 UPR·ALR 점수 캐시가 없기 때문이다. 평가는 **RRF 융합 top-5** 이므로 passage 품질이 같지 않다. 분포는 맞췄지만 내용 난이도는 맞추지 못했다.

## 10. 검증 기록

### 단위 검증 **[확인됨 — 전부 통과]**

`python test_selector_rft.py` — 4규칙 7건, 보고 버킷 5건, 파서 11건, 형식 오류 3건, 라벨 3건.

핵심 사례:
- **기권(1.0)과 형식 오류(−1.0)가 구분된다** — 합치면 기권하고 싶을 때 형식을 깨도록 학습된다
- n>0 기권과 n>0 오선택이 둘 다 0.0
- `reward()` 인자에 정답이 없음을 기계적으로 확인

### 아직 안 한 것 **[미확인]**

GPU가 기존 reader RFT 파이프라인에 묶여 있어 실행 전이다.
- Oracle-1 / Abstain-all 측정
- reader 격리 실측 (`check_reader_isolation.py`)
- GRPO 스모크 (영분산·형식 유효율)
- B / C 본 실행

## 11. 보고할 항목

- n>0 정답 근거 선택률
- n>0 에서 `source=0` 오선택률
- n=0 에서 `source=0` 선택률
- n=0 에서 passage 오선택률
- n별 선택 성능, 출력 형식 유효율
- 최종 답변 accuracy + 기존 지표
- n>0 / n=0 으로 나눈 답변 accuracy
- 영분산 그룹 비율, 실제 학습에 쓰인 그룹 수

문항별 선택·답변을 저장해 **B와 C를 paired 비교**한다 (`SelectedPassageRAG.selection_log`).

**선택률이 개선되지 않았는데 답변 정확도만 올랐다면, 그것을 "근거 선택 개선의 효과"라고 쓰지 않는다.**
