# RAG with a Small LLM — 검색 개선과 강화 미세조정

**1.24B 짜리 작은 언어모델로 open-domain QA(NQ-open)를 푸는 RAG 시스템을 만들고, 정확도를 어디까지 올릴 수 있는지 측정한 기록입니다.**

inha University CSE402 기말 프로젝트에서 출발했지만, 과제 범위를 넘어 **논문 3편의 아이디어 적용**과 **강화 미세조정(RFT/GRPO) 실험 세 건**까지 진행했습니다.

핵심 결과 하나만 먼저:

> 과제가 준 기본 RAG는 **0.2451**. 검색 쪽을 개선해 **0.3556**, 답변 모델까지 학습해 **0.3905** 까지 올렸습니다.
> 그 과정에서 **강화학습이 단순 지도학습에 졌고**, 그 이유를 측정으로 짚었습니다.

---

## 1. 배경 — RAG가 뭐고 왜 어려운가

질문에 답하려면 모델이 지식을 알아야 합니다. 작은 모델은 아는 게 적습니다. 그래서 **먼저 위키피디아에서 관련 문서를 찾아다 주고, 그걸 보고 답하게** 합니다. 이게 RAG(Retrieval-Augmented Generation)입니다.

```
질문 ──▶ [검색기] ──▶ 문서 5개 ──▶ [생성기] ──▶ 답
         BM25                      Llama-3.2-1B
```

여기서 두 군데가 고장날 수 있습니다.

1. **검색이 못 찾는다** — 정답이 든 문서가 애초에 5개 안에 없음
2. **읽고도 못 뽑는다** — 정답이 눈앞에 있는데 엉뚱한 걸 답함

이 저장소는 **둘 다 측정하고, 둘 다 고쳐보고, 어디까지 되는지 기록**한 것입니다.

### 데이터와 모델

| | |
|---|---|
| 데이터 | **NQ-open** — 구글에 실제로 입력된 질문. 정답은 평균 1~2단어 |
| 평가 | dev **6,515문항**. `best_subspan_exact_match` (정규화 후 부분문자열 포함) |
| 검색 | BM25 (Pyserini) over Wikipedia DPR 100-word split, **21,015,324 passage** |
| 생성 | **Llama-3.2-1B-Instruct** (1.24B) |
| 직접 구현 | **GPT-small** 63.58M — 4층, GQA, RoPE, RMSNorm, SwiGLU |

## 2. 전체 결과 한 장

dev 6,515문항, greedy 디코딩. 모든 설정의 분모와 질문 ID 집합이 같습니다.

| # | 시스템 | accuracy | 무엇을 바꿨나 |
|---|---|---|---|
| | **과제가 준 기본 RAG** | **0.2451** | — |
| 1 | + 프롬프트 개선 (JSON 출력 계약) | 0.2724 | 생성기 설정만 |
| 2 | + K_POOL(50) — 후보를 깊게 파고 재정렬 | 0.3361 | 검색 |
| 3 | + 정답우도 융합 + 슬롯 재배치 | **0.3556** | 검색 |
| 4 | + 답변 모델 지도학습 (gold SFT) | **0.3905** | 생성기 |
| — | *완벽한 문서 선택이라면 (진단)* | *0.4041* | — |

**1~3번은 생성기를 전혀 건드리지 않고** 무엇을 보여줄지만 바꿔서 얻은 것입니다.

## 3. 무엇을 했나 — 네 단계

### 단계 1. 검색을 깊게 파기 (K_POOL)

BM25는 **단어 겹침**만 봅니다. 질문 의도를 모릅니다.

> **질문** who sang the original version of true colors (정답: Cyndi Lauper)
> **BM25 top-5** True Colors (Zedd and Kesha) ×2 · Black Is the Color · Amy Deasismont · Queen + Paul Rodgers
> **rank 6** Change of Heart (Cyndi Lauper song) ← 정답이 바로 밖

"original"을 물었는데 커버 버전이 1·2위입니다. 단어가 더 많이 겹치니까요.

그래서 **top-50까지 파고, 생성기 자신에게 다시 순위를 매기게** 했습니다 ([UPR](https://aclanthology.org/2022.emnlp-main.249/), Sachan et al. 2022). "이 문서를 보면 그 질문이 나올 법한가"를 점수로 씁니다.

| k | 정답이 pool 안에 있을 확률 | 최종 accuracy | 소요 |
|---|---|---|---|
| 5 (기본) | 0.5285 | 0.2724 | 7분 |
| 20 | 0.7174 | 0.3213 | 20분 |
| 50 | 0.8012 | 0.3361 | 41분 |
| 100 | 0.8479 | 0.3431 | 108분 |

**깊이는 레버가 아니었습니다.** 50 → 100은 67분을 더 쓰고도 **p = 0.08** 로 노이즈와 구별되지 않았습니다. 후보 1개당 이득이 0.00110 → 0.00014 로 **8배** 떨어집니다.

### 단계 2. 논문 3편의 아이디어로 같은 pool을 더 잘 쓰기

재현이 아니라 **아이디어 차용**입니다. 셋 다 원형은 돌릴 수 없었습니다 (코드 404 / 가중치 미공개 / 베이스 모델 gated).

| 논문 | 가져온 생각 | 우리가 한 것 | 결과 |
|---|---|---|---|
| [EXIT](https://aclanthology.org/2025.findings-acl.253/) | passage 통째 대신 문장만 골라 담기 | 학습 안 된 판정기 + 토큰 예산 731 | **해로움** (0.2724 → 0.2639) |
| [InfoGain-RAG](https://aclanthology.org/2025.emnlp-main.365/) | "관련 있나"가 아니라 "정답을 끌어내나"로 순위 | gold 대신 **1라운드 예측 ŷ** 사용, RRF 융합 | **+0.72pp** |
| [GRAD](https://aclanthology.org/2026.acl-long.2099/) | 프롬프트 내 위치 편향을 상쇄 | 논문은 SLM 2개 학습 → **순서만 바꿈** | **+1.27pp** |

**GRAD 쪽이 특히 값쌉니다.** 논문은 "모든 순열을 보는 건 n!이라 비싸다"며 기각하고 학습으로 우회했는데, 우리는 **통제 실험으로 최적 순서를 직접 쟀습니다**:

정답 문서를 1~5칸에 고정하고 나머지를 정답 없는 문서로 채우면 (n=5,158):

| 정답 위치 | 1칸 | 2칸 | 3칸 | 4칸 | 5칸 |
|---|---|---|---|---|---|
| accuracy | 0.3009 | 0.3275 | 0.3532 | 0.4230 | **0.4663** |

**단조 증가, 중간 함몰 없음** (z = 24.74). 흔히 말하는 lost-in-the-middle(U자)이 아니라 **순수 recency**입니다. 그래서 최상위 문서를 **마지막 칸**에 놓는 것으로 끝냈습니다 — **추가 연산 0회로 +1.27pp** (p = 0.0029).

### 단계 3. 답변 모델을 강화 미세조정 (Reader RFT)

여기서 성격이 바뀝니다. 지금까지는 생성기를 고정했지만, 이제 **생성기를 학습**합니다.

진단이 먼저였습니다 — 정답이 프롬프트에 **있는데도** 틀린 경우가 얼마나 되나?

| | 문항 | 비율 |
|---|---|---|
| 맞힘 | 2,288 | 57.8% |
| **틀림 — 예측 문자열이 프롬프트 안에 있음** | **1,524** | **38.5%** |
| 틀림 — 프롬프트에 없음 | 144 | 3.6% |

**틀린 것의 91.4%가 "프롬프트 안의 다른 문자열"을 답했습니다.** 읽기는 읽는데 잘못 고릅니다. 검증 가능한 보상으로 고칠 수 있는 종류의 실패입니다.

그래서 출력에 **어느 문서를 썼는지 적게** 하고 보상을 설계했습니다:

```
{"answer": "Cyndi Lauper", "source": 3}

R = e + 0.3·e·g_s − 0.5·(1 − g_s)
    e   = 정답 여부
    g_s = 인용한 문서가 정답 문자열을 품었나
```

| 맞힘+근거적중 | 맞힘+오인용 | 틀림+근거적중 | 틀림+오인용 |
|---|---|---|---|
| **1.3** | **0.5** | **0.0** | **−0.5** |

모델이 스스로 8개를 생성 → 보상으로 채점 → 정답이면서 평균 이상인 것만 골라 가중 학습. 3회전.

### 단계 4. 문서 선택을 강화학습 (Selector GRPO)

반대 방향입니다. **생성기는 고정하고, 무엇을 보여줄지만 학습**합니다.

```
{"sources": [2, 4]}        ← 0~5개 아무거나. 빈 목록도 정상

R = 2·TP / (n + k)         n = 정답 문서 수, k = 고른 수, TP = 교집합
    n=0 이고 k=0 이면 1 (올바른 기권)
```

**답변 정오를 보상에 넣지 않았습니다.** 그래야 "선택이 좋아졌는가"와 "답이 좋아졌는가"를 나중에 분리할 수 있습니다.

## 4. 가장 중요한 발견 셋

### ① 강화학습이 단순 지도학습에 졌다

| 설정 | 전체 | 정답이 있을 때 | 학습 비용 |
|---|---|---|---|
| 학습 전 | 0.3316 | 0.5407 | — |
| **지도학습 (정답을 그냥 알려줌)** | **0.3905** | **0.6365** | **16분, 1회** |
| 강화 미세조정 3회전 | 0.3804 | 0.6206 | 약 4.5시간 |

```
RFT:  1회전 0.6021 → 2회전 0.6130 → 3회전 0.6206      (지도학습 0.6365)
증가폭:        +1.09pp        +0.76pp                  남은 격차 1.59pp
```

**기울기가 줄고 있어** 더 돌려도 닿기 어렵습니다. 샘플 8개 중 하나라도 맞을 확률(pass@8)이 0.6408이었는데, **지도학습이 이미 거기 0.43pp까지 닿아** 있었습니다.

### ② 보상이 가리킨 방향과 학습된 것이 어긋났다

보상은 **근거 적중에 가산점(α=0.3)과 벌점(β=0.5)** 을 줍니다. 그런데:

```
인용 적중률:  학습 전 0.5520 → 1회전 0.5258 → 2회전 0.5240 → 3회전 0.5302
             지도학습 0.5944   ← 근거 보상이 전혀 없는데 제일 높다
```

**3회전 내내 학습 전보다 낮습니다.** 이유는 명확합니다 — 지도학습은 타깃에 "정답 문서를 가리켜라"를 **직접 써줬고**, 강화학습은 모델 자신의 55% 정확도 인용 분포를 **재가중했을 뿐**입니다.

> 검증 가능한 보상을 설계했다고 해서 모델이 그 방향으로 간다는 보장은 없다.

### ③ 이 생성기에게는 정밀도보다 재현율이 중요하다

문서 선택 실험에서 나온 것입니다.

| 선택 방식 | 재현율 | 정밀도 | 답변 정확도 |
|---|---|---|---|
| 완벽 선택 (진단) | 1.000 | 1.000 | **0.6302** |
| **5개 그냥 다 넣기** | **1.000** | 0.527 | **0.5779** |
| GRPO 학습된 선택 | 0.757 | 0.635 | 0.5670 |
| 항상 1개만 | 0.356 | **0.769** | 0.5404 |

**정확히 재현율 순으로 정렬됩니다.** 정밀도가 가장 높은 쪽이 답변은 가장 나쁩니다.

그런데 우리 보상(Dice)은 정밀도와 재현율을 **대칭으로** 다룹니다. **보상의 가중이 생성기의 실제 손익과 어긋났습니다.** 선택 F1이 0.390 → 0.637로 크게 올랐는데도 "5개 다 넣기"를 못 넘은 구조적 이유입니다.

## 5. 두 축을 합치면

| | **선택 없음** (5개 전부) | 선택기 학습 전 | **선택기 학습 후** |
|---|---|---|---|
| **생성기 기본** | 0.3552 | 0.2698 | 0.3487 |
| **생성기 학습** | **0.3804** | 0.2856 | **0.3715** |

- 선택기 학습 효과는 **양쪽 생성기에서 모두 재현**됩니다 (+7.9pp / +8.6pp)
- 그런데 **선택 단계 자체가 양쪽에서 손해**입니다 (−0.65pp / −0.89pp)
- **두 축을 다 쓴 조합(0.3715)이 생성기만 학습한 것(0.3804)보다 못합니다**

## 6. 실패한 것들 — 전부 전체 6,515문항 측정

연구에서 안 된 것도 결과입니다.

| 시도 | 가설 | 결과 |
|---|---|---|
| 컨텍스트 개수 축소 | 문서를 줄이면 방해물이 준다 | **해로움** 0.2118 → 0.1975 |
| 문장 단위 압축 (EXIT) | top-20을 top-5 예산에 담으면 커버리지가 는다 | **해로움** 0.2724 → 0.2639 |
| 압축을 top-50으로 | 후보가 많아지면 정답 문장도 더 찾는다 | **부호가 뒤집힘** 0.2743 → 0.2071 |
| Chain-of-Thought | 추론을 시키면 정확해진다 | **전 지표 최하위** 0.2724 → 0.1948 |
| 최상위를 첫 칸에 | lost-in-the-middle이면 양 끝이 좋다 | **효과 없음** p = 0.84 |
| 63M 모델로 재정렬 | 작은 모델이면 20배 싸다 | **기준보다 나쁨** 0.2724 → 0.2203 |

### 측정이 해석을 뒤집은 네 번

1. **"양 끝이 좋다"** → 통제 주입 실험에서 단조 증가, primacy 없음
2. **"컨텍스트를 줄이면 방해물이 준다"** → passage 단위 1회, 문장 단위 2회, **네 번 다 해로움**
3. **"2위가 가장 위험한 오답이다"** → 순위별 측정에서 해로움이 순위와 단조 증가, 기각
4. **"프롬프트에 자리가 없다"** → 컨텍스트가 131,072 토큰인데 우리 프롬프트는 1,121 (0.9%). 잘림은 애초에 불가능

### 그리고 프롬프트 예시 하나가 강화학습을 통째로 막았다

few-shot 예시를 `[선택 시연 → 기권 시연]` 순으로 넣었더니:

| 예시 순서 | 정답이 있는데 빈 목록을 낸 비율 | GRPO 영분산 그룹 |
|---|---|---|
| 기권 시연이 **마지막** | **71.7%** | **78.8%** |
| 선택 시연이 **마지막** | 22.1% | 20% 대 |

모델은 **마지막 시연을 가장 강하게 모방**합니다. 순서 하나로 정책이 "항상 기권"에 붕괴했고, 샘플 8개가 전부 같아져 **학습 자체가 불가능**했습니다.

전부 도커 안에서 돕니다.

```bash
docker run --gpus all --rm --env-file .env \
  -v "$PWD":/workspace -v cse402-cache:/root/.cache cse402 \
  bash -lc "pip install -q peft trl; bash run_reader_rft.sh"
```

| 스크립트 | 내용 |
|---|---|
| `run_all.sh` | 사전학습 → 요약·분류·RAG 파인튜닝 |
| `run_improved.sh` | 정답우도 융합 + 슬롯 재배치 |
| `run_position.sh` | 위치 통제 실험 |
| `run_reader_rft.sh` | 생성기 RFT 3회전 |
| `run_selection_chain.sh` | 선택기 GRPO |

각 단계가 **산출물이 있으면 스스로 건너뛰므로** 중단돼도 이어서 돌아갑니다.

## 9. 한계 — 주장하지 않는 것

1. **논문 3편을 재현한 것이 아닙니다.** 아이디어만 가져왔고, 원형은 코드 404 / 가중치 미공개 / 베이스 모델 gated 로 돌릴 수 없었습니다.
2. **GRPO의 우월성을 주장할 수 없습니다.** 같은 입력·라벨로 선택기를 지도학습한 비교군이 없습니다.
3. **라벨은 문자열 일치입니다.** "정답 문자열을 포함한 문서"이지 "의미적으로 답을 뒷받침하는 문서"가 아닙니다. `1975` 같은 흔한 답은 무관한 문서에도 들어갑니다.
4. **선택된 문서를 모델이 실제로 읽고 썼는지는 확인하지 않았습니다.** 인용 적중률은 측정값이지 활용의 증거가 아닙니다.
5. **k_pool 20/50/100은 dev를 보고 고른 값입니다.** 사전 등록한 것은 "재정렬을 할지 말지"까지였습니다.
6. **dev 단일 분할**입니다. 별도 test 분할로 재확인하지 않았습니다.
7. **오라클과 11.4pp 격차**가 남아 있습니다.
